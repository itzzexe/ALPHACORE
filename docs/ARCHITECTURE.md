# Architecture

How one Node process is a whole company.

This document explains the shape of the thing and why it is that shape. The
[README](../README.md) says what it does; this says how, and what would break if
you changed it. Every number here is measured by `npm run readme:check` in the
README it came from.

---

## Four rules everything else follows from

Most of the design falls out of four decisions. If you understand these, the
rest of the code reads as consequences.

**1. One process, one file.** The HTTP server, the console, the worker loop, the
scheduler and the WebSocket are one `node` process; the whole company is one
SQLite file. There is no queue server, no reverse proxy requirement, no
container. The cost is that it scales up to a machine and not past it, which is
the intended size. The benefit is one transaction boundary and one place to look
when something is wrong.

**2. The record is append-only and hash-linked.** Every consequential act is one
row whose hash covers the row before it. `UPDATE` and `DELETE` on the audit
table are refused by SQL triggers, not by convention — so the rule holds against
anything with a database connection, including a future version of this code
written in a hurry.

**3. Money is reserved before it is spent.** A model call reserves against a
budget, then settles the real cost, then releases on failure. A report tells you
what you spent; a reservation stops you spending it.

**4. Anything that leaves the machine passes one gate**, and the intent is
written to the chain *before* the call goes out — so a blocked attempt leaves a
record too. If a rule cannot be evaluated, the call does not happen.

## The shape of a request

```
browser ──▶ server.js ──▶ auth ──▶ permission ──▶ api.js route ──▶ module ──▶ db
                │                                                    │
                │                                                    ├──▶ audit.js   (the chain)
                │                                                    ├──▶ router.js  (a model)
                │                                                    └──▶ egress.js  (the outside)
                └──▶ /live  WebSocket: presence, ticker, floor chat
```

Every `/api/*` request is authenticated before it is routed — which is why an
unknown path answers 401 rather than 404. The permission is resolved from the
path by one function, and the OpenAPI document is generated by *running* that
same resolver, so the description of the API cannot drift from the API.

The user is injected server-side. A client can ask for an action; it cannot
claim to be somebody.

## The layers

### Data — `src/db.js`

One SQLite file, 189 tables, forward-only migrations that run at import. There
is no migration tool and no down-migrations: a schema change is a `CREATE TABLE
IF NOT EXISTS` or an `ALTER TABLE` wrapped in a `try`, appended to the end. The
file is opened once and shared; `q`, `one` and `exec` are the whole interface.

`node:sqlite` rather than `better-sqlite3`, which is why Node 22.5 is the floor:
no native build, no `node-gyp`, no prebuilt binary per platform.

### The record — `src/audit.js`

```
entry = { occurred_at, actor_type, actor_id, action, subject_type, subject_id, payload }
hash  = SHA-256(canonical(entry) + previous_hash)
```

Canonical serialisation means sorted keys and no whitespace variance, so the
same entry always hashes the same. `verifyChain()` recomputes the whole chain and
names the exact entry that broke.

Hash-linking detects an editor. It cannot detect the owner of the file, who can
rewrite everything and recompute every hash — internal consistency is exactly
what a careful forger produces. So `src/anchor.js` has the chain's head witnessed
by an RFC 3161 timestamping authority on a schedule. That is the only check that
cannot be forged locally.

### The workforce — `src/workflow.js`, `src/router.js`, `src/policy.js`

An agent declares a *tier*, not a model. `router.js` resolves a tier to a chain
of provider/model candidates and walks it until one answers; a tier with no
available provider fails loudly rather than degrading silently. Reviewers are
pushed onto a different provider family than the author, because two instances
of one model reviewing each other is not review.

Runs are leased, attempted, retried with backoff, and shelved honestly when they
never succeed. Runs left `running` by a process that died are reclaimed at boot.

`policy.js` holds the reservation-first budget: `reserve(estimate)` → call →
`settle(actual)`, or `release` on failure.

### The outside — `src/egress.js`, `src/web.js`, `src/robots.js`, `src/browser.js`

Six checks in order — scope, allowlist, quota, constitution, value ceiling,
dry-run — and the intent is chained before the call. A new connector starts in
dry-run: it runs the whole path and sends nothing.

Reading the web asks first. `robots.js` implements RFC 9309 and is obeyed by the
page fetch, the intelligence crawler and the browser alike; the user-agent names
the platform and carries this install's address. A search engine results page is
refused outright, because searching goes through the engine's own interface.

`browser.js` drives a real Chrome over the DevTools protocol. The model is given
a screenshot plus every element it could actually act on, numbered — not the
HTML, because a page is forty thousand tokens of markup and about fifteen things
you can click. Anything irreversible or outward-facing stops for a person with
the screenshot attached, and a CAPTCHA ends the session.

### The rules — `src/constitution.js`

Ten rules, enforced by machine at the gate, each with a severity: `block`
refuses, `gate` stops for a person, `warn` records. They are not a document
somebody signed; they are a function the gate calls.

### The map — `src/links.js`

Every department declares what it hands to, reviews for, audits and remembers.
Those declarations are data: the console draws the map from them, the trace walks
them hop by hop, and the launch audit checks that every department is joined,
every relationship names two departments that exist, and every division touches
every other. A department connected to nothing is a finding, not a diagram
problem.

**A relationship is only declared where code really does it.** There is, for
example, no edge from Legal to the revenue loop — a contract review before a deal
is agreed is a reasonable thing to want, and nothing enforces it, so the map does
not claim it does.

### The enterprise core — `src/core2/`

The second core is the company's system of record: people and their terms,
time, money, stock, the bank, the desk, the registry. It lives in the same
process and the same database file as the AI core and is held apart by three
rules rather than by a network boundary.

**One fact, one master.** The ledger, the audit chain, customers, vendors,
contracts, projects and the device register are Core 1's. Core 2 holds facts —
a bill, a receipt, a transfer, a month of depreciation — and emits an event;
the bridge posts the entry through the same `journalEntry()` a bookkeeper uses,
with a source id so a retried event cannot post twice. `finance.js` and
`bank.js` never import `ledger.js`; the tests read the source to make sure.

**An agent never occupies a human slot.** Every reference to a person is an
INTEGER employment id in a STRICT table, and an agent's id is TEXT; the storage
engine refuses the cross-typing. There is no column anywhere for a reason, a
note or a diagnosis — a grievance, a sick note, an HR ticket's words are
documents sealed under the person they are about.

**Money leaves, and facts about people are decided, only by a person.**
Seventeen commands — `approvePayroll`, `changeSalary`, `payBill`,
`executeTransfer`, `releasePayments`, `disposeAsset`, `adoptResolution`,
`concludeCase` and the rest — are gated categorically at the bridge: a
granted scope does not clear them, `force` does not, a zero amount does not.
Each module refuses a non-human actor again as the second lock.

Five bridges and nothing else cross the seam: the MCP tool surface (one action
each, no `run_sql`), events on the durable queue, the command gateway, shared
identity, and the consequential subset of events onto the chain. The overview
atlas draws both cores on one sheet and every declared tunnel between them,
from the same catalogue and edge list the connectivity audit checks.

## What is deliberately absent

**No framework.** No React, no Express, no ORM, no bundler. The browser runs the
same JavaScript that is in the repository. The cost is hand-rolled WebSocket
framing and a hand-written PNG encoder; in a project whose argument is that the
machinery should be legible, that is the point rather than the price.

**No build step.** Nothing is transpiled. What you read is what runs.

**One dependency.** `@anthropic-ai/sdk`. Everything else is the standard library.

**No external request from the console.** No fonts, no CDNs, no analytics. This
is checked in the test sweep rather than intended.

## Extending it

A new department is not a config entry. It needs, in this order:

1. **Tables** in `db.js` — appended, never modified in place.
2. **A module** in `src/`, exporting an `overview()` and the actions it allows.
3. **Permissions** in `auth.js` — the read and each irreversible act split apart.
4. **Routes** in `api.js`, plus the path → permission line. Handlers are called
   as `handler(m.slice(1), body, url, user)`, so the first capture group is
   `p[0]` — `test/routes.test.js` fails the build on `p[1]`.
5. **A page** in `public/app.js` and an entry in `routes`. Without one the launch
   audit reports a department that cannot be opened, and that is a blocker.
6. **A place on the map** in `links.js`: the section, and edges that name code
   paths which actually exist.
7. **Tests**, and the README numbers regenerated with `npm run readme`.

[CONTRIBUTING.md](../CONTRIBUTING.md) has the house style and what the tests
expect.
